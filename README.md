# 딱맞는박스 (box-finder)

가로·깊이·높이만 입력하면 조건에 맞는 **국내 택배상자·수납함**을 개당 단가 순으로 비교해 주는 웹서비스. 현재 MVP 단계.

## 핵심 기획 포인트 — 측정 기준에 따른 양방향 필터링

사용자가 **무엇을 쟀는지**에 따라 필터 조건이 정반대로 뒤집힌다.

| 옵션 | 측정 대상 | 조건 | 비교 기준 치수 |
|---|---|---|---|
| A (기본) | 넣을 물건 | 상자가 물건보다 **크거나 같아야** 함 | 상품 **내치수** |
| B | 들어갈 선반/공간 | 수납함이 공간보다 **작거나 같아야** 함 | 상품 **외치수** |

구현에서는 분기를 두 벌 만들지 않고, `gap`("남는 여유 공간 mm")을 아래처럼 정의해 판정식을 하나로 통일했다.

- 옵션 A: `gap = 상품 내치수 - 입력값`
- 옵션 B: `gap = 입력값 - 상품 외치수`

이후 조건은 양쪽 모두 **`0 ≤ gap ≤ 허용 여유`** 한 줄. 부호 스위칭은 `fit.js`의 `calcGap()` 한 곳에만 존재한다.

## 실행

번들러·의존성 없는 순수 ES 모듈 구조라 설치 과정이 없다.
단, ES 모듈이므로 `index.html`을 더블클릭(`file://`)하면 CORS로 막힌다. **로컬 서버가 필요하다.**

VS Code 확장 [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer)를 설치하고 `index.html` 우클릭 → *Open with Live Server*.

또는 로컬에 런타임이 있다면:

```bash
python -m http.server 8792
# http://localhost:8792/index.html
```

## 랭킹 기준은 개당 단가가 아니라 '실제 지불 금액'

개당 단가로 줄을 세우면 실사용에서 오답이 나온다.

박스포유 439번은 개당 121원이지만 **176개 묶음(21,363원)이 최소 구매 단위**다.
상자 5개가 필요한 사람에게 이걸 1등으로 보여주면 안 된다. 우체국 3호 5개는 5,500원이다.

그래서 **필요 수량**을 입력받아 `ceil(필요수량 / 묶음수량) × 묶음가 + 배송비`로 실제 지불액을 구하고 그 값으로 정렬한다 (`pricing.js`).
남는 수량도 숨기지 않고 카드에 표시한다.

**배송비도 같은 이유로 포함한다.** 쿠팡 낱장 상품 중에는 개당 60원인데 배송비가 2,800원인 것이 있다.
배송비를 빼고 계산하면 이런 상품이 무조건 1등으로 올라와서 정렬이 거짓말이 된다.
`freeShippingOver`가 있으면 상품가 합계로 무료 여부를 판정한다 (무인양품 3만원 이상 무료).

실제로 같은 규격 조건에서 수량만 바꾸면 순위가 뒤집힌다.

| 필요 수량 | 1위 | 2위 |
|---|---|---|
| 5개 | 우체국 2호 **4,000원** | 우체국 3호 5,500원 |
| 93개 | 박스포유 158번 **20,454원** (딱 1세트) | 박스포유 251번 40,726원 |
| 94개 | 박스포유 251번 **40,726원** | 박스포유 158번 40,908원 (92개 남음) |
| 200개 | 박스포유 158번 **61,362원** | 박스포유 251번 81,452원 |

93개 → 94개에서 순위가 바뀌는 것에 주목. 1개 더 필요해졌다는 이유로 93개 묶음을 하나 더 사야 하기 때문이다.

## 결과 공유 링크

검색 조건이 URL 쿼리에 실린다. 새로고침해도 입력값이 남고, 링크를 그대로 보내면 상대가 같은 결과를 본다.

```
?cat=parcel&t=item&w=300&d=200&h=140&m=30&q=5&r=1
```

| 파라미터 | 의미 |
|---|---|
| `cat` | 카테고리 (`parcel` / `storage`) |
| `t` | 측정 기준 (`item` = 옵션 A / `space` = 옵션 B) |
| `w` `d` `h` | 규격 (mm) |
| `m` | 허용 여유 (mm) |
| `q` | 필요 수량 (개) |
| `r` | 가로/깊이 회전 허용 (`1` / `0`) |

`pushState`가 아니라 **`replaceState`**를 쓴다. 슬라이더를 움직일 때마다 뒤로가기 기록이 쌓이면 못 쓰기 때문이다.
URL 값은 전부 범위 검증을 거치고, 유효하지 않으면 조용히 무시하고 기본값으로 떨어진다 (`urlState.js`).

## 폴더 구조

```
box-finder/
├─ index.html                  # 단일 페이지 마크업
├─ assets/
│  ├─ css/style.css            # 모바일 퍼스트 (640px / 960px 확장), 다크모드 대응
│  └─ img/products/            # 상품 썸네일 (없으면 placeholder.svg로 폴백)
├─ data/products.json          # 더미 상품 데이터
└─ src/js/
   ├─ main.js                  # 진입점. 상태 관리 + 이벤트 바인딩
   ├─ constants.js             # CATEGORY / MEASURE_TARGET 등 상수
   ├─ fit.js                   # ★ 규격 판정 엔진 (순수 함수, DOM 의존 없음)
   ├─ repository.js            # 데이터 접근 계층 (추후 실제 API로 교체될 자리)
   ├─ pricing.js               # 필요 수량 → 묶음 단위 실지불액 계산
   ├─ urlState.js              # 검색 조건 ↔ URL 쿼리 변환 (공유 링크)
   ├─ format.js                # 원화·치수 포맷
   └─ render.js                # 결과 카드 DOM 생성
```

## 데이터 스키마

| 필드 | 설명 |
|---|---|
| `category` | `"parcel"`(택배/포장) \| `"storage"`(수납함/리빙박스) |
| `dims` | 판매처가 표기한 규격 `{w,d,h}` (mm) |
| `dimsBasis` | `"inner"` \| `"outer"` \| `"unknown"` — 위 `dims`가 무엇을 잰 값인지 |
| `wallThickness` | 벽 두께(mm). 표기 기준이 반대일 때 환산에 쓴다 |
| `verified` | 판매처 공개 정보로 확인했으면 `true` |
| `packQty` / `packPrice` / `unitPrice` | 묶음 수량 / 묶음 가격 / 개당 단가 (KRW) |
| `shippingFee` / `freeShippingOver` | 배송비 / 무료배송 기준 금액 (없으면 0 = 무료) |
| `seller` / `url` / `note` | 판매처명 / 링크 / 비고 |

### dimsBasis를 1급 상태로 둔 이유

국내 판매처는 규격이 내치수인지 외치수인지 **표기하지 않는 곳이 대다수다.** 우체국이 대표적이다.
이 서비스는 옵션 A가 내치수를, 옵션 B가 외치수를 봐야 하므로 이 구분이 정확도의 핵심인데, 원본 데이터가 그걸 주지 않는다.

그래서 추정으로 덮지 않고 세 가지 상태를 그대로 UI에 노출한다 (`fit.js`의 `resolveDims`).

| 상태 | 조건 | UI 표시 |
|---|---|---|
| `exact` | 표기 기준 = 필요한 기준 | 표시 없음 |
| `converted` | 표기 기준이 반대 → 벽 두께로 환산 | "외치수 표기를 벽 두께 3mm 기준으로 환산" |
| `unknown` | 판매처가 표기 안 함 | "⚠ 표기가 없어 내치수로 간주했습니다" |

## 데이터 수집 현황

현재 데이터는 **무인양품 8종 + 다이소몰 9종 + 쿠팡 21종**, 총 38종.

| 판매처 | 카테고리 | 상태 | 방법 |
|---|---|---|---|
| 무인양품 | 수납함 | ✅ 8종 (`dimsBasis: outer`) | 카테고리 페이지에서 `article[id]`로 상품 ID 추출 → 상세페이지에서 사이즈 |
| 다이소몰 | 수납함 | ✅ 9종 (`dimsBasis: unknown`) | 상품명에 규격이 들어있어 파싱 |
| 쿠팡 | 택배박스 | ✅ 21종 (`dimsBasis: unknown`) | **자동 수집 불가 — 사람이 페이지를 복사해 붙여넣은 것을 파싱** |

### 사이트별 접근 난이도

정적 HTML로는 대형몰을 못 읽는다. 무인양품·다이소는 **JS 렌더링 후**에야 상품 데이터가 나온다.

- 다이소몰: HTML에는 footer만 있고, 렌더링 후 상품 60개 노출. 상품명에 `24 X 32 X 12 cm` 형태로 규격이 박혀 있어 파싱이 쉽다.
- 무인양품: 목록 페이지의 `<a>`에 링크가 없고 JS 클릭 핸들러로 이동한다. 대신 `<article id="1003687">`에 상품 ID가 있어 `/products/view/{id}`를 조립할 수 있다. 상세페이지의 사이즈는 정적 HTML에도 있어 WebFetch로 읽힌다.
- 쿠팡: **모든 자동 경로가 403.** WebFetch(PC/모바일/카테고리), 인앱 브라우저 전부 차단된다.
  현재 데이터는 사람이 검색 페이지를 열어 본문을 복사해 준 것을 파싱해 넣었다. 갱신하려면 같은 작업을 반복해야 한다.
  다행히 쿠팡 상품명에는 `520 x 480 x 400mm`, `(450x320x250mm)` 같은 규격과 묶음 수량이 대부분 들어 있어 파싱 자체는 잘 된다.

`parcel` 카테고리에 상품이 하나도 없는 상황을 대비해, UI는 "규격이 안 맞음"과
**"이 카테고리에 등록된 상품이 아직 없습니다"**를 구분해 안내한다.

우체국·박스포유 데이터는 커밋 `df6046d`에 남아 있으므로 필요하면 복원할 수 있다.

## 이미지에 대한 결정

상품 썸네일은 **넣지 않는다.** 판매처 사진은 그쪽 저작물이고 핫링크는 referer 차단으로 깨진다.
대신 각 카드에서 판매처 페이지로 직접 링크한다.
