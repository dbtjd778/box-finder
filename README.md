# 딱맞는박스 (box-finder)

넣을 물건의 가로·깊이·높이만 입력하면, 그 물건이 들어가는 **국내 택배상자**를 실구매 금액 순으로 비교해 주는 웹서비스.

🌐 **https://dbtjd778.github.io/box-finder/**

## 판정 규칙

규칙은 하나뿐이다. **상자가 물건보다 크거나 같아야 한다.**

```
gap = 상자 내치수 - 물건 치수

gap < 0       → 안 들어감 (제외)
gap > margin  → 들어가긴 하지만 사용자가 정한 여유를 초과 (제외)
```

가로/깊이는 90° 돌려서 넣는 것도 허용한다(체크박스로 끌 수 있음). 높이는 세우는 방향이 정해져 있어 회전 대상이 아니다.

## 내치수/외치수 문제

이 서비스의 정확도는 **"판매처가 적어놓은 규격이 내치수냐 외치수냐"**에 달려 있는데, 국내 판매처는 이걸 표기하지 않는 곳이 대다수다.

그래서 추정으로 덮지 않고 세 가지 상태를 그대로 UI에 노출한다 (`fit.js`의 `resolveInnerDims`).

| 상태 | 조건 | UI 표시 |
|---|---|---|
| `exact` | 판매처가 내치수로 표기 | 표시 없음 |
| `converted` | 외치수 표기 → 벽 두께로 환산 | "외치수 표기를 벽 두께 3mm 기준으로 환산" |
| `unknown` | 판매처가 표기 안 함 | "⚠ 표기가 없어 내치수로 간주했습니다" |

## 랭킹 기준은 개당 단가가 아니라 '실제 지불 금액'

개당 단가로 줄을 세우면 실사용에서 오답이 나온다.

- 어떤 상자는 개당 332원이지만 **80장 묶음(26,530원)이 최소 구매 단위**다. 5개 필요한 사람에게 1등으로 보여주면 안 된다.
- 어떤 낱장 상품은 **개당 100원인데 배송비가 2,800원**이다. 배송비를 빼고 계산하면 이런 상품이 무조건 1등으로 올라와 정렬이 거짓말이 된다.

그래서 **필요 수량**을 입력받아 아래처럼 실제 지불액을 구하고 그 값으로 정렬한다 (`pricing.js`).

```
총액 = ceil(필요수량 / 묶음수량) × 묶음가 + 배송비
```

`freeShippingOver`가 있으면 상품가 합계로 무료배송 여부를 판정한다.
묶음 때문에 남는 수량도 숨기지 않고 카드에 표시한다.

수량만 바꿔도 순위가 뒤집힌다. 묶음 경계를 1개 넘기는 순간 세트를 하나 더 사야 하기 때문이다.

## 결과 공유 링크

검색 조건이 URL 쿼리에 실린다. 새로고침해도 입력값이 남고, 링크를 그대로 보내면 상대가 같은 결과를 본다.

```
?w=300&d=200&h=140&m=30&q=5&r=1
```

| 파라미터 | 의미 |
|---|---|
| `w` `d` `h` | 넣을 물건 규격 (mm) |
| `m` | 허용 여유 (mm) |
| `q` | 필요 수량 (개) |
| `r` | 가로/깊이 회전 허용 (`1` / `0`) |

`pushState`가 아니라 **`replaceState`**를 쓴다. 슬라이더를 움직일 때마다 뒤로가기 기록이 쌓이면 못 쓰기 때문이다.
URL 값은 전부 범위 검증을 거치고, 유효하지 않으면 조용히 무시하고 기본값으로 떨어진다 (`urlState.js`).

## 실행

번들러·의존성 없는 순수 ES 모듈 구조라 설치 과정이 없다.
단, ES 모듈이므로 `index.html`을 더블클릭(`file://`)하면 CORS로 막힌다. **로컬 서버가 필요하다.**

VS Code 확장 [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer)를 설치하고 `index.html` 우클릭 → *Open with Live Server*.

## 폴더 구조

```
box-finder/
├─ index.html                  # 단일 페이지 마크업
├─ assets/css/style.css        # 모바일 퍼스트 (640px / 960px 확장), 다크모드 대응
├─ data/products.json          # 상품 데이터
└─ src/js/
   ├─ main.js                  # 진입점. 상태 관리 + 이벤트 바인딩
   ├─ constants.js             # 상수
   ├─ fit.js                   # ★ 규격 판정 엔진 (순수 함수, DOM 의존 없음)
   ├─ pricing.js               # 필요 수량 → 묶음·배송비 반영 실지불액 계산
   ├─ repository.js            # 데이터 접근 계층 (추후 실제 API로 교체될 자리)
   ├─ urlState.js              # 검색 조건 ↔ URL 쿼리 변환 (공유 링크)
   ├─ format.js                # 원화·치수 포맷
   └─ render.js                # 결과 카드 DOM 생성
```

## 데이터 스키마

| 필드 | 설명 |
|---|---|
| `dims` | 판매처가 표기한 규격 `{w,d,h}` (mm) |
| `dimsBasis` | `"inner"` \| `"outer"` \| `"unknown"` — 위 `dims`가 무엇을 잰 값인지 |
| `wallThickness` | 벽 두께(mm). 외치수 표기를 내치수로 환산할 때 쓴다 |
| `verified` | 판매처 공개 정보로 확인했으면 `true` |
| `packQty` / `packPrice` / `unitPrice` | 묶음 수량 / 묶음 가격 / 개당 단가 (KRW) |
| `shippingFee` / `freeShippingOver` | 배송비 / 무료배송 기준 금액 (없으면 0 = 무료) |
| `seller` / `url` / `note` | 판매처명 / 링크 / 비고 |

## 데이터 수집 현황

현재 **쿠팡 택배박스 22종** (120×110×53mm 낱장 ~ 600×500×450mm 이사박스).

**쿠팡은 자동 수집이 전부 403이다.** WebFetch(PC/모바일/카테고리), 인앱 브라우저 모두 차단된다.
현재 데이터는 사람이 검색 페이지를 열어 본문을 복사해 준 것을 파싱해 넣었다. 갱신하려면 같은 작업을 반복해야 한다.

다행히 쿠팡 상품명에는 `520 x 480 x 400mm`, `(450x320x250mm)` 같은 규격과 묶음 수량이 대부분 들어 있어 파싱 자체는 잘 된다.

> 참고: 다이소몰·무인양품 수납함 데이터(17종)와 우체국·박스포유 택배박스 데이터(12종)는
> 커밋 이력에 남아 있다. 수납함 카테고리를 되살리려면 `c25b577`, 우체국은 `df6046d` 참고.
